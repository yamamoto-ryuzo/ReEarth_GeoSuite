📚 geosuite-hub 導入

🏠 GeoSuite トップ プラグインの配布（ZIP） GitHub で編集

公開 Visualizer シーンで利用するには viewer（WebView2）経路が実質必須です。 GeoSuite は専用プロトコル geosuite-hub:// を独自実装しており、geosuite-hub.exe の自己インストールで HKCU 登録され、--view（WebView2）を OS 経由で起動できます — KASUGAI Canvas は不要です。geosuite-hub は GeoSuite 専用インスタンス（127.0.0.1:8514）として動作し、KASUGAI 側の共有 bridge-hub（8511）とは独立です。--view が開く画面はハブの状態ページではなく、同じ exe が提供する GeoSuite viewer シェル（127.0.0.1:8515）です（後述）。

geosuite-hub（GeoSuite 専用ハブ geosuite-hub.exe と geosuite-hub:// プロトコル）の導入手順と、導入されるハブ（127.0.0.1:8514）に対する Chrome Local Network Access (LNA) による接続制約および自動アンロックの仕組みをまとめたページです。AI プロバイダ経由の使い方は bridge-hub.html、ベクターデータの外部化仕様は vector-externalization.html を参照してください。

導入方法（Ext ボタン・basemap ウィジェット／管理パネル Ext タブ）

ハブが未検出の環境ではプラグイン内に導入導線が表示されます。導入は geosuite-hub.zip（自己インストール型 geosuite-hub.exe 同梱）に統一されています — 展開して exe を1回実行するだけで、%LOCALAPPDATA%\geosuite-hub\ への自己コピー・8514 常駐のログイン時自動起動登録・8515 ビューアシェル・geosuite-hub:// プロトコル登録を一括で行います（管理者権限不要）。

  • basemap ウィジェットの Ext ボタン（v22.4.6〜・セレクタ右の小ボタン）: basemap iframe は永続するため、レイヤー読込中でも常時操作できます（レイヤーパネル iframe は ui.show のたび再生成され操作不能になるため移設）。hubCfg メッセージでパネル拡張 ctx から設定を受け取り、エンドポイント解決結果（vectorHub: > aiHub: > 127.0.0.1:8514）へ GET /health をプローブして、hub:true が返らない場合ボタンをアンバー強調します（未導入の訴求）。押下で直下のプロモ行を開閉します
  • 「geosuite-hub.zip をダウンロード」ボタン: 本リポジトリ releases/geosuite-hub.zip（hub/ クレートから tools/build_hub.py でローカルビルド・コミット済み）へリンクします（裸の .exe はサイトによってダウンロード拒否されるため ZIP 同梱）。展開して exe を実行1回で geosuite-hub.exe の自己コピー・8514 常駐の自動起動登録・8515 ビューアシェル・geosuite-hub:// プロトコル登録を行います。押下後は起動待ち表示へ切替り、/health を2秒間隔・最長3分ポーリングし、検出次第「connected」表示 → 4秒後に行を自動で閉じます（期限超過時はリトライ案内を表示）
  • プロモ行右端の − ボタン: セッション中はプロモ行とボタン/サブタブの強調を非表示にします（dismiss は basemap iframe → basemap 拡張 ctx → パネル拡張 ctx の hubPromoDismiss で中継され、セッション中 _hubPromoDismissed として保持されます）
  • プロモ行の「GeoSuite viewer で開く」リンク: geosuite-hub://open?url=<scene> カスタムプロトコル（GeoSuite 専用・HKCU 登録）経由で geosuite-hub.exe の --view（LNA 無効化済みの専用 WebView2 ウィンドウ）を OS レベルで起動します。?url= には呼び出し元ページの URL を document.referrer（sandboxed iframe からも取れる）→ location.ancestorOrigins[0] のフォールバックで自動設定します（v22.4.11〜）。--view はその URL を 8515 のビューアシェルへ転送し、シェルがそのシーンを全画面 iframe で再生し scene.txt にも記録します（?url= 無しの裸起動は従来通り記憶済みシーン or ランディングを表示）。公開シーンでは Service Worker 仲介により LNA 許可が成立しないため、この OS 経由起動がハブ利用の迂回路になります（後述の LNA 節参照）
  • 管理パネル（⚙️）の Ext サブタブ: bridge-hub: ON/OFF の状態行＋疎通確認ボタンと、レイヤーパネルと同一の導入ブロックを常設しています。「AI Bridge (CANVAS)」のエンドポイント入力（aiHub: 行と双方向同期）もこのペインに移動済みです。ハブ未検出時は Ext サブタブもアンバー強調（dismiss 後は抑制）、検出済みなら導入ブロックは自動で非表示になります
  • vectorHub: off 指定時: Ext ボタンと Ext ペイン内の bridge-hub ブロックは非表示になります（AI Bridge 設定は残ります）

geosuite-hub.zip（自己インストール型）

導入は geosuite-hub.zip に統一されています — geosuite-hub.exe を実行すると %LOCALAPPDATA%\geosuite-hub\ への自己コピー〜8514 常駐のログイン時自動起動登録（schtasks / HKCU Run キー）・8515 ビューアシェル（exe 内蔵）・geosuite-hub:// プロトコル登録（HKCU・管理者権限不要）を一括で行います。プラグインの Ext ボタン／Ext タブのダウンロードボタンはこの zip へ直リンクします。解除は geosuite-hub.exe --uninstall です。

geosuite-hub.zip をダウンロード

geosuite-hub.exe（専用ハブ）側の概要

  • 本リポジトリ hub/ クレートの独立バイナリとして提供する GeoSuite 専用インスタンス（Rust 製単一 exe・Node.js 不要・v22.4.12〜。kasugai_canvas の bridge-hub から GeoSuite 専用部分を切り離した完全分離版で、バージョンはプラグインと同一採番）。127.0.0.1:8514 にバインドして %LOCALAPPDATA%\geosuite-hub\ 配下で動作。ログイン時自動起動登録。KASUGAI の共有 bridge-hub（8511）・kasugai-hub:// とは独立で、KASUGAI 側の旧ポート掃除（8512/8513）の対象外となるポートを選択
  • プロバイダは copilot / devin / antigravity の 3 系統。実際に使われた時点で対応 CLI を子プロセス起動（未使用時はゼロコスト）。CLI 未導入なら POST /setup で公式手順の自動インストールも可能
  • 認証は CLI 側（Copilot なら copilot CLI の対話ログイン or COPILOT_GITHUB_TOKEN/GH_TOKEN/GITHUB_TOKEN）。クォータは利用者本人のものを消費
  • API: GET /health・GET /models?provider=・POST /agent・GET|POST /setup・POST|DELETE /mcp[/<project>]・GET /（状態ページ）・/vector/*（status/sources/geojson/query + probe.geojson は LNA アンロック用プローブ、v6.19.0〜）
  • GeoSuite の AI チャットが送れるのは provider:"copilot"（専用選択肢）と汎用 provider:"agent"。devin/antigravity 宛の送信は現状 GeoSuite 側 UI に無い

ハブの詳細仕様（導入・自動セットアップ・プロバイダ別前提・環境変数）は KASUGAI Canvas 側のドキュメントが正本です: ブリッジハブ（bridge-hub.exe）— KASUGAI Canvas ドキュメント

GeoSuite viewer シェル（127.0.0.1:8515・exe 内蔵）

geosuite-hub:// から開く画面専用の、ハブと同じプロセスが提供する第2の待受です。geosuite モードの geosuite-hub.exe が 127.0.0.1:8515 でビューアページを配信します（v22.4.10〜・旧 serve-viewer.ps1＋run-hidden.vbs の別プロセス構成は exe 内蔵に統合）。

  • ビューアシェルの役割: viewer.html（exe に埋め込み）は ?url=<scene> を読んでそのシーンを全画面 iframe で再生するだけの薄いシェルです。?url= 無し（裸の geosuite-hub://open や 8515/ 直アクセス）では記憶済みシーンを自動で開き、無ければ使い方とハブ状態ページ（127.0.0.1:8514）へのリンクを示すランディングを表示します（v22.4.5〜・後述）
  • 起動経路: HKCU の shell\open\command には "geosuite-hub.exe" --view "%1" を直接登録します（%1 で起動 URI をそのまま --view へ渡すため URL 書き換えシムは不要）。--view は geosuite-hub://open?url=<pct> の url= を読み、http://127.0.0.1:8515/?url=<pct> へ転送してそのシーンを開きます（シェル側で scene.txt にも記録）。url= 無しの裸起動では従来通り記憶済みシーン or ランディングが開きます（v22.4.11〜・v22.4.8〜10 は起動 URI を破棄する固定コマンドで ?url= はブラウザ直接アクセス時のみ有効でした）。ビューアシェルはハブと同じプロセスなので、ブラウザで http://127.0.0.1:8515/ を直接開くこともできます
  • 最後に開いたシーンの記憶: 内蔵ビューアサーバは GET /scene（記憶済みシーン URL を text/plain で返す）と GET /scene?set=<enc>（%LOCALAPPDATA%\geosuite-hub\scene.txt へ保存）のルートを持ちます。viewer.html は ?url= 付きで開いた際に同 URL を /scene?set= へ記録し、?url 無しでは /scene を読んで自動フォールバックします。ランディングを見たい場合は ?home を付けます（記憶済みシーンがある場合は「前回のシーン」リンクを提示し、手入力用のシーン URL 入力欄も常備）

  • 症状: Chrome 142+ では公開 HTTPS ページ上のプラグイン iframe（opaque origin）から 127.0.0.1:8514 への fetch がサイレントに拒否されます（コンソールには Permission was denied for this request to access the loopback address space）。iframe 起点では許可プロンプト自体を出せません。ハブ・ZIP・URL・CORS が全て正常でも接続できません
  • 自動アンロック（v22.4.0〜）: ハブ未検出のままユーザーが Ext を開いた時・ダウンロード後の起動待ち時に、{hub}/vector/probe.geojson を指す一時 geojson レイヤを追加し、ホスト側の data.url fetch（トップレベル発＝プロンプトを出せる唯一のコンテキスト）で許可プロンプトの誘発を試みます。検出次第プローブレイヤは自動除去（最長120秒ポーリング）。ただし公開シーンでは次項の通り成立しません
  • 公開シーン（*.visualizer.reearth.io）では機能しません（v22.4.0 実機検証・Chrome 156）: 公開サイトでは AssetSecurity 系の Service Worker（/sw.js・スコープ /）が全リクエストを respondWith(fetch(e)) で仲介し、プローブレイヤの data.url fetch はトップレベル文書発でも SW コンテキストへ移されます。SW 起点の fetch は権限プロンプトをアンカーする窓（document）を持たないため、プロンプトは出ず ~0.3s で無言の ERR_FAILED になります（ページ console に LNA エラーすら出ません）。対照として SW 非制御の公開ページでは同一 fetch がプロンプト表示待ちで pending になることを確認済みです
  • 接続経路: 公開 Visualizer シーンでは Ext プロモ行の「GeoSuite viewer で開く」リンク（geosuite-hub:// 経由で 8515 のビューアシェルを LNA 無効化済み WebView2 に開き、ページ内 iframe でシーンを再生・OS 起動のため SW の影響を受けない）が実質唯一の接続方式です。Firefox（LNA 未施行）・Chrome 起動フラグ --disable-features=LocalNetworkAccessChecks・企業ポリシーは特殊環境向けの代替で、https トンネルは /call・/agent の制御 API をインターネット公開するため実用対象外です（bridge: 行の外部ブリッジも同様）
