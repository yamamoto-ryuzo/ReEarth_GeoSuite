📚 bridge-hub 導入（Ext ボタン〜自己インストール）

🏠 GeoSuite トップ プラグインの配布（ZIP） GitHub で編集

公開 Visualizer シーンで利用するには viewer（WebView2）経路が実質必須です。 GeoSuite は専用プロトコル geosuite-hub:// を独自実装しており、workbench/geosuite-hub/install.js で HKCU 登録すれば bridge-hub.exe の --view（WebView2）を OS 経由で起動できます — KASUGAI Canvas は不要です（KASUGAI 導入環境ではセットアップが bridge-hub を自動導入します）。単体の bridge-hub.exe 導入は Workbench（localhost:8787）やイントラ内ホストなど loopback 制約の無い環境向けです — 公開 Visualizer シーンでは LNA/SW 仲介により接続経路が成立しないため、hub＋viewer の一式導入が事実上の必要条件になります。

bridge-hub（CANVAS ブリッジハブ・127.0.0.1:8511）の導入手順と、Chrome Local Network Access (LNA) による接続制約および自動アンロックの仕組みをまとめたページです。AI プロバイダ経由の使い方は bridge-hub.html、ベクターデータの外部化仕様は vector-externalization.html を参照してください。

導入方法（Ext ボタン／管理パネル Ext タブ・v22.3.0〜）

ハブが未検出の環境ではプラグイン内に導入導線が表示されます。導入は geosuite-hub-install.cmd 1本に統一されています — 実行すると bridge-hub の取得・自己インストール（%LOCALAPPDATA%\kasugairidge-hub\・ログイン時自動起動登録）と geosuite-hub:// プロトコル登録を一括で行います。

  • レイヤーパネルの Ext ボタン（レイヤー見出し「Note」の右）: パネル iframe は起動ごとに、エンドポイント解決結果（vectorHub: > aiHub: > 127.0.0.1:8511）へ GET /health を1回プローブし、hub:true が返らない場合ボタンをアンバー強調します（未導入の訴求）。押下で直下のプロモ行を開閉します
  • 「geosuite-hub-install.cmd をダウンロード」ボタン: iframe 内で統一インストーラ .cmd を生成し <a download> で保存します。実行1回で bridge-hub の取得・自己インストール（CDN から curl+tar）と geosuite-hub:// プロトコル登録を行います。押下後は起動待ち表示へ切替り、/health を2秒間隔・最長3分ポーリングし、検出次第「connected」表示 → 4秒後に行を自動で閉じます（期限超過時はリトライ案内を表示）
  • プロモ行右端の − ボタン: セッション中はプロモ行とボタン/サブタブの強調を非表示にします（dismiss 状態は _hubInstallCfg.dismissed として注入されるため iframe 再生成を跨いでも消えたまま）
  • プロモ行の「GeoSuite viewer で開く」リンク: geosuite-hub://open カスタムプロトコル（GeoSuite 専用・workbench/geosuite-hub/install.js が HKCU へ自己登録）経由で bridge-hub の --view（LNA 無効化済みの専用 WebView2 ウィンドウ）を OS レベルで起動します。開く先は設定テキストの sceneUrl: <URL> 行で指定します（sandboxed iframe は親ページの URL を読めないため、公開シーン URL はホスト側が明示する必要があります）。sceneUrl: 未設定の裸リンクはハブ状態ページ http://127.0.0.1:8511/ を開きます（?url= 省略時のフォールバックに対応した bridge-hub が必要）。公開シーンでは Service Worker 仲介により LNA 許可が成立しないため、この OS 経由起動が bridge-hub 利用の迂回路になります（後述の LNA 節参照）
  • 管理パネル（⚙️）の Ext サブタブ（v22.3.1〜）: bridge-hub: ON/OFF の状態行＋疎通確認ボタンと、レイヤーパネルと同一の導入ブロックを常設しています。「AI Bridge (CANVAS)」のエンドポイント入力（aiHub: 行と双方向同期）もこのペインに移動済みです。ハブ未検出時は Ext サブタブもアンバー強調（dismiss 後は抑制）、検出済みなら導入ブロックは自動で非表示になります
  • vectorHub: off 指定時: Ext ボタンと Ext ペイン内の bridge-hub ブロックは非表示になります（AI Bridge 設定は残ります）

geosuite-hub 統一インストーラ（推奨）

導入は geosuite-hub-install.cmd 1本に統一されています — 実行すると bridge-hub.zip の取得〜展開〜自己インストールと geosuite-hub:// プロトコル登録（GeoSuite viewer リンク用・HKCU・管理者権限不要）を一括で行います。プラグインの Ext ボタン／Ext タブのダウンロードボタンからもこの .cmd が保存されます。個別の「ZIP ダウンロード → 展開 → exe 実行」手順は不要です。開発用の Node 版登録スクリプトは workbench/geosuite-hub/install.js です。

ブリッジハブ（bridge-hub.exe）側の概要

  • Rust 製の単一 exe（Node.js 不要）で 127.0.0.1:8511 のみバインド。%LOCALAPPDATA%\kasugai\bridge-hub\ へ自己インストール＋ログイン時自動起動
  • プロバイダは copilot / devin / antigravity の 3 系統。実際に使われた時点で対応 CLI を子プロセス起動（未使用時はゼロコスト）。CLI 未導入なら POST /setup で公式手順の自動インストールも可能
  • 認証は CLI 側（Copilot なら copilot CLI の対話ログイン or COPILOT_GITHUB_TOKEN/GH_TOKEN/GITHUB_TOKEN）。クォータは利用者本人のものを消費
  • API: GET /health・GET /models?provider=・POST /agent・GET|POST /setup・POST|DELETE /mcp[/<project>]・GET /（状態ページ）・/vector/*（status/sources/geojson/query + probe.geojson は LNA アンロック用プローブ、v6.19.0〜）
  • GeoSuite の AI チャットが送れるのは provider:"copilot"（専用選択肢）と汎用 provider:"agent"。devin/antigravity 宛の送信は現状 GeoSuite 側 UI に無い

ハブの詳細仕様（導入・自動セットアップ・プロバイダ別前提・環境変数）は KASUGAI Canvas 側のドキュメントが正本です: ブリッジハブ（bridge-hub.exe）— KASUGAI Canvas ドキュメント

  • 症状: Chrome 142+ では公開 HTTPS ページ上のプラグイン iframe（opaque origin）から 127.0.0.1:8511 への fetch がサイレントに拒否されます（コンソールには Permission was denied for this request to access the loopback address space）。iframe 起点では許可プロンプト自体を出せません。ハブ・ZIP・URL・CORS が全て正常でも接続できません
  • 自動アンロック（v22.4.0〜）: ハブ未検出のままユーザーが Ext を開いた時・ダウンロード後の起動待ち時に、{hub}/vector/probe.geojson を指す一時 geojson レイヤを追加し、ホスト側の data.url fetch（トップレベル発＝プロンプトを出せる唯一のコンテキスト）で許可プロンプトの誘発を試みます。検出次第プローブレイヤは自動除去（最長120秒ポーリング）。ただし公開シーンでは次項の通り成立しません
  • 公開シーン（*.visualizer.reearth.io）では機能しません（v22.4.0 実機検証・Chrome 156）: 公開サイトでは AssetSecurity 系の Service Worker（/sw.js・スコープ /）が全リクエストを respondWith(fetch(e)) で仲介し、プローブレイヤの data.url fetch はトップレベル文書発でも SW コンテキストへ移されます。SW 起点の fetch は権限プロンプトをアンカーする窓（document）を持たないため、プロンプトは出ず ~0.3s で無言の ERR_FAILED になります（ページ console に LNA エラーすら出ません）。対照として SW 非制御の公開ページでは同一 fetch がプロンプト表示待ちで pending になることを確認済みです
  • 接続経路: 公開 Visualizer シーンでは Ext プロモ行の「GeoSuite viewer で開く」リンク（geosuite-hub:// 経由で LNA 無効化済み WebView2 にシーンを開く・OS 起動のため SW の影響を受けない）が実質唯一の接続方式です。Firefox（LNA 未施行）・Chrome 起動フラグ --disable-features=LocalNetworkAccessChecks・企業ポリシーは特殊環境向けの代替で、https トンネルは /call・/agent の制御 API をインターネット公開するため実用対象外です（bridge: 行の外部ブリッジも同様）
